# Test Cases — AI Module

> **Module:** AI (patient summary)
> **Priority:** P3 — phụ thuộc OpenAI provider; default rule-based fallback.
> **Test file:** `backend/src/ai/ai.service.spec.ts`

---

## 1. Purpose

Cover AI patient summary generation with rule-based fallback (when OpenAI not configured or fails) and Redis caching behavior.

## 2. Endpoints covered (1 endpoint)

| Endpoint | Method | Permission |
|---|---|---|
| `/api/v1/ai/summary/patient/:id` | GET | `ai.summary.read` |

## 3. Test cases

### TC-AI-001 — getPatientSummary — NotFound when patient missing

- **Verify:** `prisma.patient.findFirst({ id, deletedAt: null })` null → `NotFoundException`.

### TC-AI-002 — getPatientSummary — Returns cached summary

- **Setup:** cache hit.
- **Verify:** result has `cached: true`, no DB query for encounters.

### TC-AI-003 — getPatientSummary — Skips cache when refresh=true

- **Verify:** `cache.getJSON` not called.

### TC-AI-004 — getPatientSummary — Rule-based summary when OpenAI not configured

- **Verify:** `source: 'fallback'`, `model: undefined`.
- **Verify:** bullet `allergy` includes `allergies + chronicDiseases + currentMedications`.
